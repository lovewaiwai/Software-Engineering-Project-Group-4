# D-03 概要设计说明书

项目：SwapCampus 校园闲置物品交易平台  
版本：v1.0  
日期：2026-06-14

## 1. 设计目标

系统采用前后端分离和模块化单体架构，在课程设计阶段优先保证业务闭环、可演示性、可测试性和可扩展性。支付、柜机和 AI 均通过适配器模式隔离真实外部依赖，默认使用 Mock 实现，以降低课程周期内的联调风险。

## 2. 总体架构

```text
Vue 3 Web 前端
  -> REST API /api/**
  -> WebSocket /ws/chat

Spring Boot 后端
  -> SQL Server
  -> MinIO
  -> MockPaymentAdapter
  -> MockLockerAdapter
  -> MockAiSuggestAdapter
```

## 6. 数据设计概要

核心表分为用户域、商品域、交易域、通讯域、治理域、积分域和审计域：

- 用户域：`users`、`user_profiles`、`credit_records`。
- 商品域：`categories`、`tags`、`product_tags`、`products`、`product_images`、`product_favorites`、`browse_records`。
- 交易域：`orders`、`payments`。
- 通讯域：`chat_sessions`、`chat_messages`。
- 治理域：`reports`、`report_actions`、`user_blocks`、`user_mutes`。
- 积分域：`point_tasks`、`point_records`、`point_redemptions`。
- 审计域：预留或实现审计日志能力。

## 7. 安全设计

- 用户密码使用 BCrypt 存储。
- 前端登录后保存 JWT，调用接口时携带 `Authorization: Bearer <token>`。
- 后端通过 Spring Security 解析 Token 并注入当前用户上下文。
- 管理端接口限制管理员角色访问。
- 被封禁用户禁止继续访问受保护业务接口。
- 实名信息仅在必要页面展示，联系方式采用脱敏展示。

## 8. 扩展点

| 扩展点 | 当前实现 | 后续升级 |
| --- | --- | --- |
| 支付 | `MockPaymentAdapter` | 支付宝、微信、校园卡 |
| 柜机 | `MockLockerAdapter` | 真实校园柜机开放平台 |
| AI | `MockAiSuggestAdapter` | 大模型或机器学习定价服务 |
| 推荐 | 规则加权推荐 | 协同过滤、向量推荐 |
| 存储 | MinIO / 本地静态 | 云对象存储、缩略图服务 |

## 9. 部署架构

Docker Compose 启动以下服务：

- `sqlserver`：SQL Server 2022。
- `db-init`：重建数据库并执行迁移和种子脚本。
- `minio`：本地对象存储。
- `backend`：Spring Boot 后端。
- `frontend`：Vue 静态服务。

## 10. 质量保障

- 后端执行 `mvn test` 和 `mvn verify`。
- 前端执行 `npm run build`。
- Docker 执行 `docker compose --profile app config --quiet` 和镜像构建。
- GitHub Actions 在 push 和 PR 时执行后端测试、前端构建和 Docker 构建检查。

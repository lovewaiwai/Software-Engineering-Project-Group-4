# D-02 需求规格说明书 SRS

项目：SwapCampus 校园闲置物品交易平台  
版本：v1.0  
日期：2026-06-14

## 1. 引言

SwapCampus 是面向本校师生的校园闲置物品交易平台。系统通过学号实名验证、信用分、站内聊天、交易评价、举报审核和管理员后台，替代微信群、朋友圈等分散式交易方式，提升校内闲置物品流转效率和交易可信度。

## 2. 用户角色

| 角色 | 说明 | 主要权限 |
| --- | --- | --- |
| 游客 | 未登录访问者 | 浏览公开商品、查看商品详情、注册、登录 |
| 买家 | 已实名用户 | 搜索、收藏、聊天、下单、支付、确认收货、评价、举报 |
| 卖家 | 已实名用户 | 发布商品、编辑商品、接单、确认交付、查看评价 |
| 管理员 | 平台治理人员 | 商品审核、举报处理、用户管理、数据看板 |
| 系统管理员 | 系统维护人员 | 分类标签、柜机、审计日志、系统配置 |

## 3. 功能需求

### M1 用户体系

| 编号 | 需求 |
| --- | --- |
| FR-M1-01 | 用户可使用用户名和密码注册登录。 |
| FR-M1-02 | 登录成功后系统签发 JWT，前端携带 Bearer Token 调用受保护接口。 |
| FR-M1-03 | 用户通过学号实名验证沙箱后，才可发布商品、下单、支付和评价。 |
| FR-M1-04 | 用户可维护昵称、头像、学院、年级、联系方式等个人资料。 |
| FR-M1-05 | 系统维护信用分，默认 60 分，变化写入 `credit_records`。 |
| FR-M1-06 | 系统提供签到、任务、积分流水和积分兑换能力。 |

### M2 商品发布

| 编号 | 需求 |
| --- | --- |
| FR-M2-01 | 卖家可发布商品，填写标题、描述、分类、标签、价格、成色、交易方式。 |
| FR-M2-02 | 商品支持多图展示，图片可存储于 MinIO 或本地静态资源。 |
| FR-M2-03 | 商品发布后进入待审核状态，管理员审核通过后上架。 |
| FR-M2-04 | 卖家可编辑、下架、重新上架自己的商品。 |
| FR-M2-05 | 商品状态包括草稿、待审核、上架、审核拒绝、锁定、售出、下架。 |

### M3 商品检索

| 编号 | 需求 |
| --- | --- |
| FR-M3-01 | 用户可按关键词搜索商品标题、描述。 |
| FR-M3-02 | 用户可按分类、价格区间、成色、校区、交易方式筛选商品。 |
| FR-M3-03 | 用户可按最新、价格、热度、推荐等维度排序。 |
| FR-M3-04 | 系统记录浏览行为，用于推荐和运营看板。 |
| FR-M3-05 | 系统提供个性化推荐流，冷启动时返回热门和最新商品。 |

### M4 交易流程

| 编号 | 需求 |
| --- | --- |
| FR-M4-01 | 买家可对已上架商品发起订单，同一商品同一时间只允许一个有效订单锁定。 |
| FR-M4-02 | 卖家可确认或取消订单。 |
| FR-M4-03 | 系统支持 Mock 支付，支付成功后生成支付流水。 |
| FR-M4-04 | 系统支持线下面交确认和校园柜机中转。 |
| FR-M4-05 | 订单取消、退款、争议、关闭均应记录状态变化。 |
| FR-M4-06 | 交易完成后可评价，评价影响信用分。 |

### M5 站内通讯

| 编号 | 需求 |
| --- | --- |
| FR-M5-01 | 买卖双方可围绕商品或订单创建会话。 |
| FR-M5-02 | 聊天支持文本、图片、表情消息。 |
| FR-M5-03 | 新消息通过 WebSocket 推送，失败时可使用 HTTP 轮询降级。 |
| FR-M5-04 | 系统记录未读数、已读时间和消息发送状态。 |

### M6 后台管理

| 编号 | 需求 |
| --- | --- |
| FR-M6-01 | 管理员可审核待发布商品，通过或拒绝并填写原因。 |
| FR-M6-02 | 用户可举报商品、订单或聊天消息。 |
| FR-M6-03 | 管理员可处理举报：驳回、下架商品、警告用户、封禁用户、进入争议订单。 |
| FR-M6-04 | 管理员可查看用户、商品、订单、举报等运营数据。 |
| FR-M6-05 | 关键管理操作写入审计日志。 |

## 4. 附加功能

| 附加项 | 需求说明 |
| --- | --- |
| 个性化推荐 | 基于浏览、收藏、分类偏好和商品热度加权推荐 |
| AI 分类定价 | 使用规则 Mock 返回分类、标签和价格区间建议 |
| 校园柜机中转 | 使用 Mock Locker 生成柜机任务、柜门、取件码 |
| 信用积分游戏化 | 支持签到、任务、积分记录、积分兑换信用修复或商品曝光加速 |

## 5. 非功能需求

| 类别 | 需求 |
| --- | --- |
| 性能 | 聊天单页面延迟目标不超过 200ms；商品列表接口 95% 响应时间目标不超过 500ms |
| 安全 | 密码 BCrypt 加密，JWT 鉴权，后台接口按角色授权，实名信息脱敏展示 |
| 可用性 | 主流程可在桌面浏览器完成，移动端可浏览和下单 |
| 可维护性 | 后端按业务模块拆包，前端按页面、组件、API、状态分层 |
| 可测试性 | 核心业务规则有单元测试或接口测试记录 |
| 可扩展性 | 支付、柜机、AI 使用 Adapter 隔离，默认 Mock，可替换真实服务 |

## 6. 关键业务流程

### 6.1 最小演示流程

```text
注册登录 -> 实名验证 -> 卖家发布商品 -> 管理员审核通过
-> 买家搜索商品 -> 聊天 -> 下单 -> 卖家确认
-> 模拟支付 -> 面交/柜机交付 -> 确认收货 -> 评价 -> 信用分更新
-> 举报商品 -> 管理员处理 -> 审计日志
```

### 6.2 订单状态机

```text
CREATED -> SELLER_CONFIRMED -> PAYMENT_PENDING -> PAID -> DELIVERY_PENDING -> RECEIVED -> COMPLETED
```

异常状态：

```text
CANCELLED, REFUNDING, REFUNDED, DISPUTED, CLOSED
```

## 7. 验收标准

- 完成 6 个必做模块。
- 至少提供买家、卖家、管理员 3 类演示账号。
- 至少提供 200 条商品种子数据。
- 支持站内聊天演示，目标延迟不超过 200ms。
- 单元测试覆盖率目标不低于 60%，最终数值以 JaCoCo 报告为准。
- 提交完整文档、管理表单、源代码仓库和演示脚本。

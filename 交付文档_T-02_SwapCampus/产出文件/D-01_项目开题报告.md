## 1. 项目背景

校园内每年都会产生大量闲置教材、电子产品、生活用品和运动用品。当前交易主要依赖微信群、朋友圈或线下口口相传，信息分散、搜索困难、商品状态不透明、交易信用难追溯，管理员也难以及时发现违规商品和争议交易。SwapCampus 面向本校师生构建一个校园二手交易平台，以实名、信用分、站内沟通和后台治理为核心，提高闲置物品流转效率与交易可信度。

## 2. 建设目标

本项目目标是在课程设计周期内完成一个可运行、可演示、可测试的 Web 平台，支撑“实名用户 -> 发布商品 -> 商品审核 -> 搜索浏览 -> 买卖沟通 -> 下单支付 -> 面交或柜机交付 -> 评价信用更新 -> 举报处理”的完整业务闭环。

核心目标如下：

- 完成 T-02 要求的 6 个必做模块：用户体系、商品发布、商品检索、交易流程、站内通讯、后台管理。
- 至少实现 3 类用户角色：买家、卖家、管理员。
- 使用 JWT、学号实名验证沙箱和信用分流水建立可信用户体系。
- 使用 WebSocket 或轮询降级方式支持站内即时沟通。
- 使用 Mock Payment、Mock Locker、可选 DeepSeek AI 与 Mock 兜底等适配器支撑演示闭环和扩展性。
- 通过 Docker Compose 提供本地一键启动方式。

## 3. 需求范围

### 3.1 必做范围

- 用户注册、登录、实名验证、个人主页、信用分记录。
- 商品发布、编辑、图片、分类、标签、价格、成色、审核与上下架。
- 商品关键词搜索、分类浏览、价格区间、成色和交易方式筛选。
- 订单创建、卖家确认、模拟支付、面交确认、评价与信用分变更。
- 买卖双方站内聊天，支持文本、图片、表情和未读状态。
- 管理员商品审核、举报处理、用户管理和数据看板。

### 3.2 附加范围

- 基于浏览、收藏、分类偏好的个性化推荐。
- AI 自动分类与定价建议，课程阶段使用规则 Mock。
- 校园柜机中转，课程阶段使用 Mock Locker。
- 签到、任务、积分兑换等信用积分游戏化能力。

## 4. 技术方案

| 层次 | 方案 |
| --- | --- |
| 前端 | Vue 3 + Vite + TypeScript + Element Plus + Pinia + Vue Router |
| 后端 | Spring Boot 3 + Spring Security + JWT + MyBatis-Plus |
| 数据库 | SQL Server 2022 |
| 对象存储 | MinIO，支持本地静态资源降级 |
| 即时通讯 | Spring WebSocket，保留 HTTP 轮询降级 |
| 部署 | Docker Compose |
| 测试 | JUnit 5、Mockito、前端构建检查、接口测试、性能测试预留 |

## 5. 可行性分析

业务上，校园二手交易场景真实、需求明确，团队成员就是目标用户，便于调研和验证。技术上，前后端分离、SQL Server、JWT、WebSocket、Docker Compose 都是课程和常规工程实践中可掌控的技术。风险较高的真实支付、真实柜机和真实 AI 服务均通过 Mock Adapter 替代，并保留接口扩展点，因此不会阻塞主流程。

## 7. 风险与应对

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 即时通讯联调复杂 | 影响买卖沟通演示 | 优先保证文本消息，图片/表情作为增强；保留轮询降级 |

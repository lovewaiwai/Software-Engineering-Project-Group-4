# D-04 详细设计说明书

项目：SwapCampus 校园闲置物品交易平台  
版本：v1.0  
日期：2026-06-14

## 1. 分层设计

后端采用以下调用层次：

```text
Controller -> Service -> Mapper -> SQL Server
                  -> Adapter -> Mock/Real Provider
```

- Controller 负责参数接收、鉴权边界、响应封装。
- Service 负责编排业务流程和规则校验。
- Mapper 负责 MyBatis-Plus 数据访问。
- Adapter 隔离支付、柜机、AI 等外部服务。

## 2. 统一响应与错误处理

统一响应结构：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

分页响应结构：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 200
}
```

业务异常统一通过 `BusinessException` 抛出，由 `GlobalExceptionHandler` 转换为稳定错误响应。

## 3. 核心状态机

### 3.1 商品状态

```text
DRAFT -> PENDING_REVIEW -> ACTIVE -> LOCKED -> SOLD
                |             |
                v             v
          REVIEW_REJECTED   OFFLINE
```

规则：

- `ACTIVE` 商品才可被搜索、收藏、聊天和下单。
- 买家创建有效订单后商品进入 `LOCKED`。
- 订单取消或关闭后商品回到 `ACTIVE`。
- 订单完成后商品进入 `SOLD`。

### 3.2 订单状态

```text
CREATED -> SELLER_CONFIRMED -> PAYMENT_PENDING -> PAID -> DELIVERY_PENDING -> RECEIVED -> COMPLETED
```

异常状态：

```text
CANCELLED, REFUNDING, REFUNDED, DISPUTED, CLOSED
```

| 当前状态 | 动作 | 下一状态 |
| --- | --- | --- |
| CREATED | 卖家确认 | SELLER_CONFIRMED |
| CREATED | 买家或卖家取消 | CANCELLED |
| SELLER_CONFIRMED | 创建支付单 | PAYMENT_PENDING |
| PAYMENT_PENDING | 支付成功 | PAID |
| PAID | 选择交付方式 | DELIVERY_PENDING |
| DELIVERY_PENDING | 买家确认收货或取件成功 | RECEIVED |
| RECEIVED | 双方评价或自动完成 | COMPLETED |
| 任意进行中 | 举报争议成立 | DISPUTED |
| DISPUTED | 管理员关闭 | CLOSED |

## 4. 关键业务设计

### 4.1 注册登录

用户提交用户名和密码，后端校验唯一性并使用 BCrypt 存储密码哈希。登录成功后签发 JWT，返回 Token 和用户摘要信息。

### 4.2 学号实名验证

实名验证使用沙箱数据。用户提交学号、姓名和教务密码，系统验证通过后写入实名状态。每个学号只允许绑定一个启用账号。

### 4.3 商品发布与审核

卖家填写商品信息并提交后，商品进入待审核状态。管理员可通过或拒绝，拒绝时填写原因。审核通过后商品对买家可见。

### 4.4 搜索与推荐

商品搜索支持关键词、分类、价格、成色、交易方式和分页。推荐流基于浏览记录、收藏、分类偏好、商品热度和新鲜度加权计算。商品曝光加速通过 `boosted_until` 字段实现，未过期的加速商品在搜索排序中优先展示。

### 4.5 下单与支付

买家对上架商品下单后，系统锁定商品并创建订单。卖家确认后创建支付单。Mock 支付确认成功后订单推进到已支付状态，并进入交付流程。

### 4.6 面交与柜机中转

面交流程由双方线下完成，前端按钮模拟确认交付和确认收货。柜机中转由 Mock Locker 生成柜机任务、柜门、寄件二维码文本和取件码，前端按钮模拟寄件、取件。

### 4.7 评价与信用分

交易完成后买卖双方可评价。信用分变化规则：

| 事件 | 分值 |
| --- | --- |
| 完成交易 | +2 |
| 获得好评 | +1 |
| 有效举报 | -5 |
| 违规商品下架 | -10 |
| 爽约或恶意取消 | -3 |
| 积分商城信用修复 | +5，且最高不超过 100 |

所有信用分变化写入 `credit_records`，并限制分值范围为 0 到 100。

### 4.8 积分商城

积分用于游戏化权益，与信用分分离。用户可签到、完成任务获得积分；积分可兑换信用分修复或商品曝光加速。兑换时校验余额、兑换限制、商品归属和商品状态。

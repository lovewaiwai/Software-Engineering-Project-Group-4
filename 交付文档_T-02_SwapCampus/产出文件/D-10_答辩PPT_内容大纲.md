# D-10 答辩 PPT 内容大纲

项目：SwapCampus 校园闲置物品交易平台  
建议页数：10-12 页  
演示时长：5-8 分钟

## 1. 封面

- SwapCampus 校园闲置物品交易平台
- T-02 课程设计
- 第 4 组
- 成员：罗正青、周济、李泰合、罗宇、董浩田
- 指导教师：王升

## 2. 项目背景与痛点

- 校园闲置物品多，微信群和朋友圈交易分散。
- 信息搜索困难，商品状态不透明。
- 信用难追溯，违规商品和争议交易难治理。
- 目标：建立实名、可信、可沟通、可治理的校园交易平台。

## 3. 业务目标与角色

- 买家：搜得到、看得清、聊得通、买得放心。
- 卖家：发布快、曝光高、回款准。
- 管理员：审核商品、处理举报、维护秩序。
- 完整闭环：实名 -> 发布 -> 审核 -> 搜索 -> 聊天 -> 下单 -> 支付 -> 交付 -> 评价 -> 治理。

## 4. 功能模块

- M1 用户体系：实名、信用分、个人主页。
- M2 商品发布：多图、分类、标签、成色、价格。
- M3 商品检索：关键词、分类、高级筛选、推荐。
- M4 交易流程：下单、支付、面交、评价。
- M5 站内通讯：实时聊天、图片、表情。
- M6 后台管理：商品审核、举报处理、用户管理。

## 5. 系统架构

- 前端：Vue 3 + Element Plus。
- 后端：Spring Boot 3 + Spring Security + MyBatis-Plus。
- 数据库：SQL Server。
- 对象存储：MinIO。
- 部署：Docker Compose。
- 外部依赖：Mock Payment、Mock Locker、Mock AI。

## 6. 核心业务设计

- 商品状态机。
- 订单状态机。
- 信用分流水。
- 积分商城与商品曝光加速。
- 举报处理和审计追踪。

## 7. 数据库设计

- 用户域、商品域、订单域、聊天域、举报域、积分域。
- 展示 ER 图或核心表关系。
- 强调 200 条商品种子数据和演示账号。

## 8. 项目亮点

- 完整交易闭环。
- 实名 + 信用分可信体系。
- WebSocket 站内聊天。
- Mock Adapter 保证可演示和可扩展。
- Docker 一键启动。
- CI 自动执行测试和构建。

## 9. 测试与质量

- 后端 `mvn test` 通过，19 个测试。
- 前端 `npm run build` 通过。
- Docker Compose 配置校验通过。
- 风险：JaCoCo 行覆盖率当前约 14.60%，距离课程目标 60% 仍需补测。
- 待补：接口测试集合、性能测试数据、灰度用户反馈。

## 10. 演示流程

1. 卖家登录并发布商品。
2. 管理员审核通过。
3. 买家搜索商品并进入详情。
4. 买卖双方聊天。
5. 买家下单，卖家确认。
6. 买家模拟支付，双方确认面交。
7. 买家评价，信用分变化。
8. 买家举报违规商品，管理员处理。
